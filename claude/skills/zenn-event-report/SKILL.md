# Zenn イベントレポート作成

ユーザーが渡す「学習メモ」を入力に、Zennに投稿できるイベントレポートの下書きを作る。

## 入力
- 必須: 学習メモ(箇条書き・断片的でよい)
- 任意: イベント名、開催日、URL、登壇者名、資料リンク、想定読者、出力先ディレクトリ
- 不足している必須情報(イベント名・日付)は最初に1回だけまとめて質問する。メモだけで進められるなら質問せず進める。
- 出力先が指定されていない場合は、ファイルを書く前に出力先を質問する。勝手にカレントディレクトリ等へ書き出さない。

## 守るルール
- メモにない事実を書かない。補完が必要な箇所は `【要確認】` と明示する。
- 登壇者の発言を捏造しない。引用は短く、メモにあるものだけ使う。
- 所感・学び・業務への活かし方は、メモに書かれた内容をユーザー自身の言葉に近い形で整える。メモにない所感を新しく作らない。足りなければ `【所感を追記】` のプレースホルダーを置く。
- 文体はユーザー指定があればそれに従う。なければ「です・ます調」。
- スライドのスクリーンショットは載せない前提で書き、貼る場合は撮影・掲載可否の確認を促す。

## 出力: Markdownファイル
ユーザーが指定した出力先ディレクトリに保存する(存在しない場合は作成してよいか確認する)。同名ファイルが既にある場合は上書きせず確認する。
ファイル名は `YYYY-MM-DD-イベント名の英数字スラッグ.md`。内容は次の構成。

### frontmatter
```
---
title: "【イベント名 参加レポート】学びのひとこと"
emoji: "📝"
type: "tech"   # 技術解説中心ならtech、体験・感想中心ならidea
topics: ["イベント名", "技術名"]   # 最大5個、小文字・英数字推奨
published: false   # 下書きは常にfalse
---
```

### 本文構成
1. **概要**: イベント名、日付、開催形式、どんな人向けか、この記事で得られること(冒頭数行)
2. **セッション別まとめ**: セッションごとに「内容の要点 / 自分が学んだこと」。登壇資料へのリンクがあれば各セッション末尾に置く
3. **全体を通しての所感**: メモ由来の気づき、業務での活かし方、次のアクション
4. **参考リンク**: イベントページ、登壇資料、関連記事

## 公開前チェックリスト(下書きの最後に添える)
- [ ] `【要確認】` `【所感を追記】` をすべて解消した
- [ ] 登壇資料・参考元へのリンクを入れた
- [ ] 画像・スライドの掲載がイベントのルール上OKか確認した
- [ ] topics を設定した(最大5個)
- [ ] 登壇者名・社名・技術名の表記ゆれ、誤字を確認した
- [ ] イベント後1週間以内の公開を目指す
- [ ] `published: true` に変更した

## レビュー(ユーザーが依頼したときのみ)
ユーザーから下書きのレビューを頼まれたときだけ実施する。下書き作成時に自動では行わない。

- 対象ファイルを先に読む。
- 確認する観点は次の2つ。
  - 文脈: 前後のつながり、主張と根拠の対応、セッション間・所感との整合に違和感がないか。
  - 構成: 本文構成(概要 / セッション別まとめ / 所感 / 参考リンク)の順序・粒度・過不足に違和感がないか。
- 自動修正はしない。ファイルを書き換えず、指摘のみを返す。
- 指摘は「該当箇所 / 違和感の内容 / 修正案」の形で挙げる。修正するかどうかはユーザーが決める。
- 違和感がなければ、その旨を一言で伝える。

## 仕上げ
作成後は、ファイルの保存先(フルパス)と、ユーザーが埋めるべき箇所(`【要確認】`等)の数を1〜2文で伝える。
